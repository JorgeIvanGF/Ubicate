## Diferenciar Grant y RLS

- **Grant ausente:** el rol no puede acceder al objeto/columna; documentación oficial de Supabase describe respuesta PostgREST SQLSTATE `42501` con permiso denegado y hint. No debe diagnosticarse como policy RLS.
- **Grant presente y RLS filtra:** un SELECT puede devolver `200` con `[]`; una mutación puede devolver cero filas o error de policy/check, dependiendo del endpoint/payload. Aceptación: confirmar estado final mediante lectura y no solo status HTTP.
- **JWT ausente/incorrecto:** puede quedar en contexto `anon` o ser rechazado por Auth/API gateway. En ambos casos debe probarse que no obtiene datos o acciones de `authenticated`.

No se fija ahora una expectativa de status exacto donde dependa de versión/configuración. Antes de ejecutar, registrar versiones, grants y forma observada de cada respuesta.
